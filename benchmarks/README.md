# Performance budgets

Run from a fresh checkout with Node 24 and the Go version in `go.mod`:

```sh
node benchmarks/run.mjs
```

The command prints its result and artifact directory. Use `--out DIRECTORY` to
choose a new directory for a comparison run. Dependencies and the Go toolchain
must be installed or downloadable on the first run. The measured workloads use
no network services, GitHub requests, credentials, or personal Codex files.

## Workloads

| Path | Small | Large | Measured production work |
| --- | --- | --- | --- |
| Go PR rendering | 20 PRs | 500 PRs | Table cells, Unicode widths, formatting, writing to a discard writer |
| Go issue rendering | 20 issues | 500 issues | Table cells, Unicode widths, labels, formatting and writing |
| Go status rendering | 20 PRs and 20 issues | 500 PRs and 500 issues | Status header, both tables and a workflow run |
| Go monitor reconciliation | 20 rows | 500 rows | Key lookup, stable order, diff summaries and sorting |
| Node Codex cold snapshot | 4 sessions, 10 turns each | 80 sessions, 100 turns each | SQLite query, file stats, JSONL parsing, aggregation and sorting |
| Node Codex warm snapshot | Same small fixture | Same large fixture | SQLite query, file stats and cached-rollout aggregation |

Go records have stable numbers, mixed states, Unicode titles, review/check
states, labels and relationship text. Monitor refreshes remove 10% of the old
rows, add the same number of new rows and modify another 10%; 80% stay unchanged.
Fixture construction and one renderer/reconciler warm-up are outside `B.Loop`.
Rendering runs with piped stdio and color disabled, without terminal-width
truncation. These are local display operations, not subprocess startup or API
fan-out benchmarks. Existing behavior tests cover command execution separately.

Node creates a private temporary Codex home with a real SQLite database and
one rollout file per session. Each file has one task-start record and three
records per turn: prompt, tool call and token usage. The workloads contain 124
and 24,080 records respectively. Their generated byte sizes appear in the raw
Node output. A fixed clock keeps every session in the query window. Every
snapshot must return the expected session, request, tool and token totals.
The process removes only its own temporary fixture directory on completion.

Cold means an empty adapter rollout cache. It does not mean a flushed operating
system disk cache. Each sample creates a new adapter, measures its first
snapshot, then measures the next snapshot through the same adapter. Two full
cold/warm pairs warm V8, modules and OS file caches before seven measured pairs.
This exercises the real adapter and SQLite implementation without mocks.

## Baselines and ceilings

`baseline.json` records the initial seven samples and machine metadata.
`budgets.json` is the enforced ceiling for every metric. Baseline ratios are
reported for comparison; they do not normalize results across different CPUs.
Changing either file requires review alongside the workload definitions.

Initial reference: Windows x64, AMD Ryzen 9 9950X3D, 32 logical CPUs, about
64 GiB RAM, Go 1.26.7, Node 24.12.0. CI runs on a shared `ubuntu-latest` x64
runner with Node 24 and Go from `go.mod`. The artifact records the actual CPU,
OS, runtime versions, revision and dirty state on every run. CPU contention,
storage, antivirus and runtime changes can affect results. Compare runs on the
same machine before drawing conclusions about smaller changes.

| --- | --- | --- | --- |

Go uses one logical execution thread, seven samples, `-benchmem` and a 150 ms
minimum timed interval per sample. Go's `B.Loop` excludes fixture setup and
keeps the measured calls alive. Reported time is ns/op, alongside B/op and
allocs/op. There is no race or coverage instrumentation in benchmark runs.

Node measures elapsed milliseconds with `performance.now()`. Memory is the
increase in `process.memoryUsage().heapUsed` after forced GC relative to the
pre-adapter heap, keeping the adapter cache and current snapshot alive. Warm
memory uses the same pre-adapter reference, not the cold snapshot as its base.
GC and validation are outside the elapsed interval. Negative heap differences
from unrelated collection are recorded as zero. This is retained V8 heap,
not allocation volume, peak memory, RSS or SQLite's native memory.

### Variance policy

A metric fails only when at least six of its seven samples exceed its absolute
ceiling. One or two scheduler/GC outliers cannot fail CI. A missing path,
unbudgeted path, wrong sample count or invalid number fails immediately.
The report includes all samples, min/median/max, exceedance count and baseline
ratio. The test suite checks isolated noise, sustained regressions and missing
evidence explicitly.

These are conservative regression ceilings, not a statistical significance
test or a claim to detect a 10% latency change on shared hardware. Latency
ceilings allow roughly four to six times the initial reference measurements;
allocation ceilings allow about 30–50% growth. Node memory ceilings include a
GC noise allowance. A sustained ceiling breach is a failure even if the host is
busy. Investigate it and rerun on an idle comparable host; do not automatically
retry until a passing result appears or automatically raise the baseline.

## CI and evidence

The `Performance Budgets` job is part of the required `Quality Gate`. It measures
changes to `src/**`, `benchmarks/**`, Go dependencies, CI and its ruleset
validator, or quality-tool pins. PRs compare the entire PR against its base;
pushes compare their before/after commits. Manual/called CI always measures.
Unrelated documentation changes skip measurement but still test the gate.
Missing Git comparison data fails rather than silently skipping a benchmark.

The suite normally takes tens of seconds with cached dependencies. Child
process limits allow two minutes for Go and one minute per Node workload;
metadata commands have ten-second limits. The CI job has a ten-minute timeout
including tool setup and upload. Benchmark cases contain no sleeps or external
services. The job uploads artifacts on pass or failure and retains them for
30 days:

- `go.stdout.txt` and `go.stderr.txt` preserve raw Go benchmark output.
- `node-small.*.txt` and `node-large.*.txt` preserve workload sizes, raw timings,
  retained heap samples and runtime diagnostics.
- `metadata.json`, `baseline.json` and `budgets.json` identify the compared
  environment and policy.
- `report.json` contains samples and the full baseline/budget comparison.
- `error.txt` records subprocess, timeout or collection failures when no full
  comparison can be produced. Earlier raw outputs remain available.

To check the detector itself, run `node --test benchmarks/*.test.mjs`. For a
full sensitivity check in a disposable worktree, temporarily retain an extra
4 MiB allocation inside `renderPullRequestRows`, run the documented command,
and confirm its B/op ceiling fails. Restore that exact edit and rerun. Keep
the failing and restored artifact directories separate. Never commit the
injected allocation or regenerate budgets from the deliberately slowed run.
